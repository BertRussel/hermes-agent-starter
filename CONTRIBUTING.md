# Contribution policy

This candidate uses one canonical source per role and a tested public/native alias mapping. Propose changes in a scoped feature workspace; do not modify owner-controlled main, live profiles or Gateway services. Read definitions/usages and project rules before edits.

For behavior changes use causal RED→GREEN tests, then regression and extracted-byte acceptance. Source tests run with `python3 -B -m pytest -q -p no:cacheprovider`. Preserve negative privacy, traversal, tamper, authority and lifecycle gates. Unit tests cannot substitute for clean onboarding, live owner routes or exact-head independent acceptance.

Dependency/source updates require exact provenance, public redistribution rights, retained notices and compatibility evidence. Never label private adaptation permission as a public license. Keep credentials, identity overlays, private receipts, sessions, caches, jobs, backups and historical factory source out of public export/history.

Protected instruction edits retain the genuine guarded route. Detached makers return excluded inert path/hash-bound proposals; no shell-write, copy-transform, rename or context-spoof bypass.

Freeze complete changes and actual head/tree before independent verification and dependent review. The controller owns acceptance; foreground owner-authorized publication alone writes public source/assets. Report actual tool/test output and any genuine remaining gate; do not fabricate passing results.
