# Eight worked workflows

These are fictional, expected walkthroughs, not fabricated execution receipts. Local measurements are identified separately in [capability status](CAPABILITY-STATUS.md). Full clean-user execution on an accepted public payload remains mandatory. Each route inherits the actor/version/privacy limits in its linked chapter.

## 1. First owner setup: Mira and Alex

Actor: Alex, fictional owner. Input: the blank-inspiration [astronomy form](../examples/fictional-personal-assistant/customization.json), accepted release inventory and an absent private home. Prerequisite: public runtime/source rights and independent acceptance; current candidate has not met them.

1. Independently download the accepted asset, verify checksum/notices and exact extraction inventory.
2. Follow [isolated installation](bible/03-installation.md), rebuilding dependencies without factory auth or a copied venv.
3. Copy the fictional form outside the clone, replace the private path/model selection and run `python3 -B scripts/validate_customization.py /absolute/private/customization.json`.
4. Expect validated/local-only/installed-false; no owner fields are printed. This is not rendered Soul acceptance.
5. Through the guarded owner route, review consistent private Soul/USER/MEMORY/Bible seeds and record approval before installation. This seed step remains implementation-gated.
6. Choose a new or existing knowledge vault explicitly. Alex supplies credentials through native setup and performs harmless real inference/messaging tests privately.

Independent check: a second observer compares the accepted asset hashes, private identity consistency and real test receipts. Recovery: retain the previous owner environment and refuse unresolved placeholders, overwrite or inherited auth. Outputs: private form, approved identity and acceptance record, never public Git.

## 2. Install an accepted specialist: implementer

Actor: owner/operator. Input: extracted canonical forge distribution and source hash inventory; public implementer maps to native forge.

1. Preflight accepted native `hermes profile install --help` in the intended isolated home.
2. Run `hermes profile install /absolute/extracted/profiles/forge --name forge` without force/alias/activation.
3. Verify native target root and all source-owned payload hashes; distribution provenance/timestamp is runtime-owned metadata.
4. Attempting the same install again must refuse the existing profile, not overwrite it.
5. Admit an implementation task only through the controller's blocked/link/timing/release sequence; installation alone never launches it.

Measured local supplement: the exact-byte six-profile canary performs native install, negative repeated install, same-version update, private export/import and hash checks. Recovery: preserve an existing profile and inspect the narrow failure. Outputs: isolated source distribution and private installed profile, not a live Gateway mutation.

## 3. Coding through review and remediation

Actor: owner-facing controller, implementer, independent verifier, dependent reviewer. Fictional input: add a deterministic garden schedule parser; no account/production scope.

1. Freeze expected result, causal tests, repository/parent/paths/commands and authority packet.
2. Create blocked root, attach/read exact notify+wake route, start/read installed timing, then release root.
3. Create implementer blocked; link prerequisites→implementer and implementer→root, validate packet and native admission before release. Native Gateway alone launches.
4. Implementer verifies clean base, observes one behavioral RED, applies minimal ordinary code, proves GREEN/regression and freezes committed source with actual native evidence.
5. Controller independently reproduces output and pre-creates blocked verifier/reviewer, reviewer depending on verifier; seal same-head packet and release verifier only.
6. If verifier reports a concrete defect, preserve failed evidence and use the allowed bounded remediation child, then fresh source/evidence/reviews. On PASS release dependent reviewer against unchanged bytes.
7. Controller owns final acceptance and terminal timing. Public/production delivery remains a separate grant.

Independent check: actual task/run order, head/tree/artifact hashes, commands and verdicts. A local DB dependency test cannot stand in for this real admitted loop. Recovery: no duplicate root, historical task release or fabricated PASS. Outputs: private task evidence and accepted candidate code.

## 4. Research: fictional garden water needs

Actor: admitted researcher; controller checks decisive claims. Inputs: precise question, permitted public source classes and private report path.

1. Read owning project and source/index records. Define the claim and confidence standard.
2. Open primary sources, record retrieval date and cite exact supporting passages. Check conflicting recommendations and relevance to the actual fictional scenario.
3. Use bounded read-only leaves only for independent lanes, not final decision ownership; verify returned claims yourself.
4. Report findings, contradictions and uncertainty without implementing purchases/automation.
5. File accepted durable findings under Research, update Research Index and link the owning project.

Independent check: controller opens cited sources and validates material claims. Recovery: permitted documented alternatives for blocked fetches, with missing evidence stated explicitly. Outputs: private cited report/index update. No live external research is claimed from a local RSS fixture.

## 5. Creative artifact: original geometric garden mark

Actor: designer; separate critic and owner approval. Inputs: original harmless SVG, required dimensions/formats, legal backend and QA contract.

1. Check source/reference rights and retain editable original.
2. Render through an approved legal backend; check SVG validity and output dimensions/alpha bounds.
3. Change original geometry in a disposable fixture, re-render and prove expected changed-pixel bounds; identical-image comparison alone is insufficient.
4. Inspect actual image visually and reopen final formats. Native critic reviews the frozen artifact independently; owner decides final creative/public use.
5. Deliver a real file/attachment and verify exact target receipt when authorized.

Measured local supplement: factory Inkscape geometry and changed-pixel QA passed on private selected source. It does not clear proprietary source public rights or editorial approval. Recovery: inspect legal supported alternatives and preserve original/last-valid render. Outputs: editable source, candidate image and private technical/visual QA.

## 6. Interrupted-task recovery

Actor: native controller. Input: exact interrupted run, immutable source/artifact hashes and checkpoint.

1. Read native task/run/claim/dependency state and current source; do not infer failure from chat silence or PID.
2. If only the observer failed, repair that observer, not the task graph. If waiting on a child, retain child→root and typed dependency parking.
3. Preserve interrupted test output as non-evidence. Resume through authentic native recovery against the exact stop and permitted authority.
4. Reverify source identity, stale evidence and all affected gates before fresh acceptance; do not reconstruct timing gaps.
5. Record current state and human-facing task view from native authority.

Independent check: task run history and real timing/source lineage. Recovery limit: genuine policy/credential/approval gates go to the specific owner/controller operation, no guard clearing or new dispatcher. Outputs: private attributable recovery record.

## 7. Update preserving customization

Actor: owner/operator. Input: prior/next accepted version, private Soul/config/memory/vault hash inventory and rollback plan.

1. Read [native update limitations](bible/22-updates.md): distribution-owned Soul is overwritten, config preserved by default and local/memories user-owned.
2. Back up privately and restore into an absent isolated home/name. Credentials require a separate secure recovery route.
3. Install the next source in another disposable home. Apply approved identity preservation through guarded supported routes, never blind force/update over personalized Soul.
4. Exercise actual version migration and negative failure; compare every private hash and vault link before real switch.
5. Retain old accepted source until owner acceptance; real activation/Gateway lifecycle belongs only to the owner-approved operator.

Measured supplement: same-version native refresh/export/import passes; cross-version preservation/rollback is still a gate. Independent check: exact versions, untouched private hashes and real rollback proof. Recovery: keep old environment on any mismatch. Outputs: private backup and versioned acceptance record, never a public archive.

## 8. Restore into a clean home

Actor: owner/operator; independent observer. Input: credential-free private native profile export, separate knowledge backup, accepted runtime and secure owner credential recovery.

1. Verify backup hash/source and absent target. Inspect safe archive inventory before importing.
2. Use native profile import into an absent isolated profile; do not overwrite a current owner home.
3. Compare restored identity/config/local/memory hashes and separately restore/verify vault links without replacing existing knowledge.
4. Rebuild dependencies from source/locks; do not copy old venv. Run local canaries and actual owner-only inference/messaging only after native reauthentication.
5. Test that a repeated restore refuses the existing destination. Record source, versions, actual results and any unsupported migration.

Measured supplement: the six-profile canary uses native export/import and exact private-file hashes. Full clean-home/vault/credential recovery and release-download trial remain pending. Outputs: private restored home and acceptance record. Recovery: preserve original backup and refuse unsafe members/unsupported versions before mutation.
