# Complete-system operating procedures

These procedures supplement the owner's existing identity and knowledge. They
are not permission to install, authenticate, publish, launch workers or overwrite
instructions. Current candidate status is blocked, not target accepted.

## Canonical factory gate

From the admitted repository workspace, the sole full-system entry point is:

    python3 -B scripts/acceptance.py --bundle-source <approved-Hermes-source> --output-dir .full-system-proof --fixture-root .full-system-fixture

The source argument must equal the immutable factory card binding. A different
source is rejected, not silently used. This path first runs the full repository
suite, then reads approved objects, applies explicit recipient adaptations,
scans complete selected bytes, emits manifests/reproducible source archives,
restores those archives and rebuilds isolated runtime environments. Logs and
source ledgers stay in attributable private factory proof directories. They are
not recipient attachments. A nonzero exit and `acceptance: blocked` are
intentional while mandatory native/profile/inference gates remain open.

The historical Git-bundle builder is not an alternative full-system acceptance
path. Do not update legacy truth files merely to conceal a canonical failure.

## Prepare and install

1. Review source rights, immutable hashes, architecture and the complete matrix.
2. Preserve the owner's identity, customizations and vault. Discover existing
   layout without importing private factory context.
3. The sanctioned controller must resolve the protected-copy gate before six
   profile packaging or native installation: the native installer stages and
   copies profile instructions even when those instructions are unchanged.
4. Use native distribution dry-run/plan, then install under an explicitly
   disposable home first. Confirm the installed managed bytes against the exact
   archive manifest and native distribution receipt. Do not use live profile
   exports, hand-created operational config or stubbed Hermes installations.
5. Rebuild dependencies for the actual platform, run pip check and all positive
   canaries. Then separately approve target installation. A factory smoke test
   is not the recipient's owner acceptance.

No automatic bootstrap is currently claimed for the six profiles: instructions
are deliberately absent from the ordinary worker's source archives until the
controller-only protected route is authorized.

## Backup and restore

Native profile backup artifacts may contain private identity, customizations,
sessions or credentials. Keep them private, encrypted/access-controlled as
appropriate and excluded from public source export. Never run a backup against
a live home merely to populate a factory test. In a permitted disposable test,
create a known user customization, take a native backup, restore to a fresh
home and compare both managed and user-owned bytes/modes. Archive primitive
roundtrip is already exercised but does not substitute for native profile
backup/restore. Record exact commands, exit codes and restored evidence.

## Update and rollback

Native update changes only receipt-managed files. Dry-run first. Preserve local
edits, omitted user-owned files and owner identity; reject conflicts instead of
forcing replacement. Exercise a reviewed changed distribution and an untouched
owner customization in an authorized disposable home, check the update receipt
and then restore the previous exact accepted managed bytes. Compare hashes,
permissions and customization preservation after rollback. Do not change the
accepted package merely to make rollback look successful. Native receipt paths,
backup mechanism and compatibility rules must come from the pinned runtime,
not a hand-built parallel updater.

## Native work pipeline

The primary controller owns one durable root and its explicit scope. Create the
maker blocked, establish dependencies, native-admit and release it to the
Gateway dispatcher. Implementation reports real tests and immutable Git/source
binding. Precreate both blocked Independent Verifier and Eve cards, seal the
same exact packet, then admit/release Verifier. Verifier PASS permits Eve on
unchanged bytes; the controller makes the final decision. Remediation requires
fresh bounded authority and resealing. Keep installed timing evidence linked to
the same root, children, phases and final decision. Timing never dispatches.

No wrapper launch, shadow scheduler, generic helper-as-profile, manual workspace
override or controller callback is part of this package. Local database lifecycle
canaries validate machinery only and are not agent inference.

## Creative quality

The actual vector adapter renders original harmless geometry with Inkscape. QA
uses real decoded pixels, explicit known bounds and a changed-geometry comparison;
not merely file existence. Studio's fixture adapter and doctor are readiness
checks, not real model-child work. Art must retain editable source and provenance,
complete its allowed Designer/Critic process when configured, and leave creative
approval with the owner. Never infer taste from technical metrics. The approved
Chromium adapter fails closed as unavailable; do not remove that isolation gate
or describe it as a verified browser runtime.

## Supporting workflows

Rebuild the supporting environment from `requirements-host.txt`, then call
`supporting_runtime.runtime.local_canary` with a new output directory. It creates
and reopens actual DOCX/XLSX/PDF/raster files and preserves local RSS source links.
It does not calculate spreadsheet formulas, verify real external facts, produce
audio/video or connect accounts. A parsed citation proves a feed assertion only.
`supporting_runtime.runtime.media_canary` separately generates and reopens
original PCM audio and, when FFmpeg plus ffprobe are provisioned, encodes an
actual MPEG-4 video and probes its codec/dimensions. Missing or failing video
dependencies return an explicit blocked status rather than a fake result.
FFmpeg is an external host prerequisite, not a bundled binary or target
compatibility claim. Advanced dependencies, external research and browser
canaries remain explicit runtime-coverage gates, not invisible optional exclusions.

## Secrets, jobs and accounts

Source verification uses a scrubbed environment and never inherits provider,
cloud, profile or account credentials. No job is activated. If an approved
inference gate requires credentials, the controller must provide a separately
scoped isolated in-memory mechanism without printing, persisting or inheriting
factory secrets. The recipient supplies their own accounts, identity and final
permissions. Authentication success does not authorize sending, publishing,
purchases, financial actions, destructive changes or other production mutations.

## Incident and rollback evidence

Preserve failing receipts rather than deleting them. Attribute every output
before cleanup. Report the exact first failing command and unexercised mandatory
gates. Do not publish proof ledgers with private paths/identifiers. The installed
system must remain unchanged during factory verification and protected-file
whole-root guards must be checked independently by the controller.
