# 8. Memory, skills and continuity

## Actor and authority
The owner approves stable facts. Each role follows its memory/write boundaries. A proven reusable skill is procedure memory, not new authority.

## Prerequisites and version
Use native memory/skills on the accepted runtime. Specialist candidate configs disable persistent owner memory. Skill references and executable dependencies must be installed and source-reviewed before use.

## Inputs
Confirmed facts, task checkpoints, source links, corrections and reviewed reusable procedures.

## Procedure
Keep identity anchors and stable environment facts compact; do not put task queues, installation progress, secrets or entire manuals in memory. File project knowledge in the owning vault note and link it from an index. Before a recurring procedure, discover and load the relevant installed skill/reference. After compaction, reload any pruned skill rather than acting on a placeholder. Before continuing a task, read its native card, prior attempt evidence, current source identity and latest checkpoint. Treat stale worker summaries as claims, not present state. Record corrected assumptions where future workers will discover them; do not overwrite unrelated profile skills as housekeeping.

## Expected results
A new session locates the authoritative task, repository, knowledge and procedure without conversation history. Stable memory remains small and task-specific records stay out of global identity.

## Independent verification
Start a fresh disposable session or owner-operated continuation trial and trace discovery from the task/card and indexes. Verify skill linked files exist and tests exercise the real procedure, not a parallel test-only model.

## Failure and recovery
Missing skills/references are narrow dependency gates. Preserve the last verified checkpoint and source hashes. Reload source authority after a stale or interrupted session; never reconstruct missing acceptance or timing receipts from memory.

## Privacy and outputs
Memory and session histories remain private. Public examples contain fictional facts only. There is no claimed automatic bulk MEMORY import in this starter.
