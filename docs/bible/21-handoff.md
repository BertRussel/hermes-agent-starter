# 21. Install verification and handoff

## Actor and authority
A new owner/operator independently validates the released payload. The controller makes the final acceptance decision; factory preparation cannot certify owner access or acceptance.

## Prerequisites and version
Frozen reviewed release/head/tree, public source/rights clearance, deterministic checksums, complete docs and a clean supported environment with no factory HOME or ambient credentials.

## Inputs
Acceptance matrix, fictional identities A and B, capability inventory, exact extracted distributions and owner's separately supplied credential route where authorized.

## Procedure
Download the reviewed release independently, compare hashes and extract safely. Rebuild dependencies, install all six distributions, verify role/config boundaries and run documented local canaries. Validate two unrelated customization forms, one blank inspiration; render/review private identity seeds only through the genuine guarded route. Create or map knowledge without overwrite. Execute a real admitted task loop with verifier→reviewer order and an intentional recovery/remediation. Exercise backup/restore and a real version change/rollback while preserving private identity/memory/vault. Record live model/messaging results only from actual approved target tests. Remove temporary operator access through the owner-controlled account process after handoff.

## Expected results
An acceptance record maps every criterion to real output/command/receipt and exact released bytes. Unit tests, inventory and archive reproducibility remain supplemental evidence.

## Independent verification
An independent reviewer follows only released docs, checks all links/commands and reproduces clean onboarding. Public remote readback and fresh download are mandatory before release completion.

## Failure and recovery
Any missing required gate keeps full-system release unaccepted. Report exact remaining owner/source/backend gate without silently reducing the outcome or fabricating model responses.

## Privacy and outputs
Keep identities, credentials, access removal and target receipts private. Public acceptance summary contains sanitized capability/version results only.
