# 12. Implementation loop

## Actor and authority
The implementer owns integration within the admitted repository/paths/commands. It cannot widen production, public, credentials, protected instruction or next-stage authority.

## Prerequisites and version
Native code card version native-kanban-code-v1, exact base commit, clean dispatcher workspace and origin. Genuine mutations do not require a future head or frozen bytes before work.

## Inputs
Canonical repo, origin remote, expected parent, allowed paths/commands, prohibited actions and acceptance tests. Read applicable project rules and locate definitions/usages before editing.

## Procedure
Run raw Git root/HEAD/object/origin/status checks and fail closed on mismatch or dirt. Do not invoke native post-commit evidence prematurely. For behavior changes write one causal failing test, observe RED, implement the smallest fix, then focused GREEN and regression checks before the next behavior. Use file tools for ordinary edits and preserve protected-write guards. Isolate any source-editing leaf in an explicitly authorized exclusive worktree; read-only helpers cannot become formal acceptance roles. Capture checkpoints before long gates. Inspect changed source, untracked files, dependencies/notices and privacy. Commit only the admitted integrated candidate; derive actual head/tree/parent, run the exact installed native validator and freeze only after acceptance.

## Expected results
Working code has real execution evidence, no stubs/fabricated output and no unrelated edits. Changed paths stay within the exact card bounds.

## Independent verification
The controller reruns deterministic gates and verifies artifact identities. A maker's green test or summary is not independent acceptance. Re-read current status before relying on a session-start snapshot.

## Failure and recovery
A setup/import error is not behavioral RED. Diagnose root cause before repeated fixes. Preserve failures and return a precise path/hash-bound gate for protected or owner-only operations, without silently narrowing the outcome.

## Privacy and outputs
No secrets, logs, private proof homes or generated junk in source commits. Excluded inert proposals are not loaded instructions.
