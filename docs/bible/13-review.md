# 13. Verification and independent review

## Actor and authority
The controller first independently reproduces maker evidence. The verifier then owns a fresh attributable formal verdict; the dependent reviewer evaluates identical bytes after PASS. The controller owns remediation routing and the final decision.

## Prerequisites and version
Frozen actual source head/tree/parent, clean workspace, complete changed-path inventory, exact artifact hashes, scope-bound commands and sealed native packet binding both reviewer IDs.

## Inputs
Full aggregate change set, source/license/privacy evidence, executable acceptance matrix and exact-head test results. Transport checkpoints never hide earlier unaccepted changes.

## Procedure
Reproduce repository identity and every required deterministic gate independently. Pre-create both reviewer cards blocked and dependency-link reviewer behind verifier before sealing. Admit/release only verifier. PASS requires every named criterion actually exercised; missing, skipped, stale or failed checks are not PASS. On terminal PASS, admit the dependent reviewer against the same sealed packet and unchanged bytes. Neither formal reviewer delegates a verdict or repairs source. A concrete defect returns through the supported bounded remediation route, followed by fresh freeze, verification and review. Packet-only correction does not invent a source defect or consume a substantive remediation without cause.

## Expected results
Two attributable verdicts refer to one immutable candidate, with reproducible commands/results and explicit pending gates. No manual/advisory substitute masquerades as formal acceptance.

## Independent verification
Read native task/run identity, dependency order and sealed source/artifact digest. Rehash the candidate after every stage. Any byte change invalidates exact-head acceptance, including test-only edits.

## Failure and recovery
Fail closed on malformed verdicts, mismatched heads, unauthorized writes or budget exhaustion. Preserve failed runs; controller routes the narrow corrective operation rather than starting a competing graph.

## Privacy and outputs
Keep review reports and source receipts private unless separately sanitized for publication. Never include credentials or raw private evidence in durable metadata.
