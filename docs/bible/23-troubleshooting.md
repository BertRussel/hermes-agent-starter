# 23. Troubleshooting

## Actor and authority
The owning actor diagnoses within admitted scope. Workers cannot restart live services, clear guards, alter credentials or release historical tasks because a test failed.

## Prerequisites and version
Actual native task/source/backend identity and documented help for the accepted runtime. Record the real exit status before cleanup can mask it.

## Inputs
Exact failed command/operation, source/head/tree, sanitized log, last verified checkpoint, capability prerequisites and source ownership.

## Procedure
Classify the failure first: package/import/dependency; unsupported runtime/API; auth/provider; backend availability; native admission/dependency; notification/timing; stale review; output delivery. Verify immediate prerequisites and locate the owning definition/usages. Reproduce the smallest permitted failure, then add a causal negative if changing behavior. If dependencies rebuild but a browser backend is unavailable, inspect documented alternatives; do not claim universal browser inability. For native dispatch, read actual task/edges/claim/run state; never create another controller or standalone launch. For timing, compare immutable evidence/report. For stale review, freeze new bytes and route fresh independent acceptance. For delivery, read the exact target rather than retrying blindly.

## Expected results
A specific root cause and smallest corrective operation are supported by tool output. Setup failures are not behavioral RED, partial tests are not release PASS, and one transport failure is not proof of no capability.

## Independent verification
Repeat the corrected route and regression gates from the final unchanged source. Reconcile late background results by process/source lineage; stale successful output cannot certify newer edits.

## Failure and recovery
After repeated unexplained failures, use systematic root-cause analysis rather than looping. Genuine human/policy gates preserve exact path/hash-bound resume steps and attributable partial evidence. Interrupted runs remain non-evidence.

## Privacy and outputs
Sanitize logs before durable comments. Never paste tokens, auth stores, private DOM or unrelated state into reports.
