# Storage Operations Hub

## Purpose and justification

This hub exists because notes, source code, original files, documents, runtime state and credentials have different authorities and approval boundaries. It is a routing map, not a new file service, scheduler, credential store or claim of configured access.

## Current state

All external connections are unverified until the owner approves and tests them. Map existing equivalents before adding a vault or storage system. Do not copy an existing private vault into this starter.

## Routing matrix

| Material | Authority | Vault role |
| --- | --- | --- |
| compact confirmed stable facts | native memory | pointer only when useful |
| reusable execution procedures | skills | linked accepted runbook/context |
| durable knowledge and decisions | Obsidian | canonical readable note with owning index |
| application source | Git/GitHub | source pointer and accepted decision |
| original media/editable documents | exact file or collaboration store | verified location, owner, access status |
| optional OCR/search archive | justified document archive | selective index, not the only original |
| sessions, jobs, logs and databases | native runtime | redacted state/evidence pointer only |
| secret values and OAuth tokens | approved credential/provider-owned route | no values, only safe authority/presence map |

## Safe defaults and approvals

Read-only inventory and reversible drafts remain within explicit scope. Moving/deleting originals, sharing/uploading, production, public sends, spending, accounts/access and new credentials require applicable owner authority. A derived export is not permission to delete an original. Login never grants downstream action authority.

## Evidence and recovery

Verify exact source/destination and hashes for an approved copy, reopen the destination, and retain originals. Interrupted side effects remain unknown until exact target readback. Backups need scoped exclusions, encryption as appropriate, retention and a harmless restore rehearsal; local copies do not establish off-host disaster recovery.
